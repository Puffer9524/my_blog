## 写在前面

本文是个人博客的第一篇文章，旨在记录搭建这个博客的初衷、过程与技术选型，同时对未来的内容方向做一个简要的规划。如果你也在考虑搭建自己的技术博客，或许本文能提供一些参考。

## 一、为什么需要一个博客
我目前是计算机专业本科在读，后分流至人工智能方向。坦诚地说，在技术领域我尚未有什么建树，和身边大多数同学一样，经历着某种程度的迷茫——知道应当努力，却时常缺乏明确的方向；渴望创新，却不知从何入手。

这种状态持续了一段时间后，我意识到需要一个具体的、可长期运作的项目来打破这种循环。这个项目的定位可以是多重的：

- **面向就业的附加项目**：在简历上呈现一个持续维护的个人站点，体现工程实践能力；
- **技术学习的驱动力**：通过定期输出学习笔记和项目记录，反向推动自己持续输入；
- **个人表达的出口**：作为分享生活、输出观点的私域空间；
- **社交名片**：让感兴趣的人能够通过这个站点了解我的技术方向与思考方式。

触发我真正开始行动的原因，要回溯到大二学习前端开发的那段时间。在掌握了 HTML、CSS、JavaScript 三件套之后，我接触到了 Vue 框架，第一次感受到前端开发不仅仅是"把界面做出来"，更像是用代码进行设计表达——逻辑与视觉在此交汇，功能与美学在此统一。那些结构清晰、交互流畅的优秀项目让我意识到，通过自己的代码也可以创造出类似的东西。这个想法像一颗种子一样埋了下来。

而让种子发芽的，是今年以来 AI 辅助编程工具的快速进步。它们大幅降低了陌生技术栈的入门成本，让"从零搭建一个网站"这件事不再需要耗费大量时间在环境配置和文档查阅上。于是，当初那个想法终于具备了落地的条件。

## 二、技术选型与搭建过程

### 2.1 框架选择：Astro

本博客使用 **Astro** 作为静态站点生成框架。选择 Astro 主要基于以下几点考虑：

- **岛屿架构（Islands Architecture）**：允许在静态页面中嵌入动态交互组件，不同组件可以使用不同的前端框架，且仅在需要时加载客户端 JavaScript，兼顾了开发灵活性与运行时性能；
- **内容优先**：对 Markdown 和 MDX 的原生支持使得内容创作体验流畅，符合博客类站点的核心需求；
- **较低的迁移成本**：未来如果需要引入 React、Vue 或 Svelte 组件，可以在不重构整个项目的前提下增量添加。

### 2.2 类型系统：TypeScript

项目使用 TypeScript 进行类型约束。坦白说，我对 TypeScript 的掌握尚处于初级阶段，在开发过程中遇到了不少类型定义方面的问题。但正是通过这次实际项目的驱动，我对泛型、类型推断、接口定义等概念有了比以往更具体的理解。我认为这是一种有效的学习方式——在实际需求中学习，而不是脱离上下文地记忆语法。

### 2.3 部署与域名

- **部署平台**：Netlify。其与 Git 仓库的集成部署流程较为简洁，且提供免费的 CI/CD 服务，适合个人项目的快速上线。
- **域名**：在阿里云购买。这里需要提及一个细节：购置域名后需要完成备案和 DNS 解析配置，涉及 CDN 加速、SSL 证书绑定等步骤——对于一个之前只关注代码层面的开发者来说，这些运维侧的工作确实增加了不少认知负担。在这个过程中我对 DNS 解析记录（A 记录、CNAME）、TLS 证书续期等概念有了实操层面的认知。

此外，我还基于项目需求开发了一个小型插件，具体功能与实现细节将在后续文章中展开。

## 三、搭建过程中的几点体会

回顾整个搭建过程，虽然技术难度不算高（多数问题可以通过查阅文档和借助 AI 工具解决），但我认为有几个层面的收获值得记录：

**第一，从"使用者"到"构建者"的视角转换。** 以往使用各类开发工具和服务时，很少关注其背后的配置逻辑。实际搭建一个需要对外服务的站点，迫使我去理解域名解析、CI/CD 部署、静态资源托管等平时被封装好的环节，这对建立完整的工程视野是有帮助的。

**第二，学习的内化发生在解决问题的过程中。** AI 工具可以快速给出答案，但真正的理解来自追问"为什么"和"还有没有更好的方式"。搭建过程中我刻意避免"复制粘贴即完成"的工作方式，而是要求自己在拿到解决方案后去理解其原理。

**第三，项目规模与学习效率之间存在平衡点。** 博客这类项目体量适中——既不像 todo 应用那样过于简单、无法覆盖足够多的技术点，也不像大型企业级应用那样需要庞大的前期投入。对于学生阶段的开发者来说，是一个性价比较高的实践项目。

## 四、内容规划与更新计划

本博客未来的内容方向主要包括以下几类：

1. **技术学习笔记**：围绕人工智能专业课程和自学内容，整理学习过程中的重点、难点与思考；
2. **项目推进记录**：分享个人项目的开发进度、技术决策与迭代过程；
3. **兴趣相关分享**：涉及阅读、工具、效率方法等与技术人生活相关的主题；
4. **个人随笔**：偶尔记录阶段性感悟与思考。

关于更新频率，目前暂定随缘更新——即在有值得记录的内容时产出，不刻意追求周更或月更。相较于频率，我更希望保证每篇文章的信息密度和可读性。

## 五、结语

这篇文字既是对博客成立的说明，也是给自己的一份记录。写下这些时，我并不确定这个博客能持续多久、能产出多少内容——但我确定的是，做这件事本身已经让我收获了一些东西：对完整工程流程的了解，对技术细节的深化，以及一个可以持续投入的长期项目。

如果你也在犹豫是否要开始一个类似的个人项目，我的建议是：先做起来，在迭代中完善。准备工作永远可以"更充分"，但开始本身就是最重要的一步。

未来这个博客会走向哪里，我也很好奇。如果有缘读到这里的你感兴趣，欢迎偶尔回访。
